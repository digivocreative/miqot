# Audit keamanan, bug, dan performa — 30 Oktober 2026

Audit mencakup Express, autentikasi agent dan Portal Jamaah, integrasi AWAPI/legacy, dokumen/PDF, webhook deployment, build frontend/PWA, konfigurasi container, dependensi npm, serta pengujian unit/integrasi/browser. Perbaikan berada di working tree; layanan produksi tidak di-restart atau di-deploy oleh audit ini.

Pengujian perubahan menggunakan checkout sementara dengan dependensi dari lockfile baru, database tiruan, dan akses jaringan eksternal yang diblokir pada server pengujian. Pemeriksaan database produksi hanya membaca kontrol akses anonim. Tidak dilakukan submit pendaftaran, pembayaran, pengiriman notifikasi, migrasi database, atau stress test pada layanan produksi.

Browser baru menyimpan metadata routing/offline; sesi lama ditukar ke cookie sebelum salinan bearer dihapus. Link akses booking yang memang reusable tetap reusable. |

## Dependensi

Audit npm awal: **56** temuan (2 critical, 26 high, 24 moderate, 4 low).

Setelah perbaikan lockfile: **4 low**, **0 moderate/high/critical**. Audit khusus dependensi produksi (`--omit=dev`): **0 kerentanan**. Vite dinaikkan ke 6.4.5 dan Sharp ke 0.35.5 yang mendukung Node 20. Pembaruan lain mengikuti rentang versi kompatibel, termasuk jsPDF 4.2.1, MCP SDK 1.32.2, Axios 1.21.0, dan Undici 7.30.1.

Empat temuan low berasal dari rantai build `deepmerge → @rollup/plugin-node-resolve → workbox-build → vite-plugin-pwa`. Audit tidak memaksakan downgrade PWA untuk menyembunyikan advisory. Tinjau ulang ketika upstream menyediakan perbaikan yang kompatibel. Referensi: [advisory deepmerge](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), [advisory jsPDF](https://github.com/parallax/jsPDF/security/advisories), [advisory MCP SDK](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories), [advisory Vite](https://github.com/vitejs/vite/security/advisories).

## Optimasi performa

- Request jadwal serentak saat cache kosong memakai satu proses pembentukan respons per tahun. TTL dan bentuk payload tetap sama. Invalidation memiliki generation guard agar proses lama tidak menimpa cache baru setelah sync.
- Penulisan `last_active_at` Portal Jamaah hanya dilakukan setelah jeda lima menit; request baca berikutnya dalam jendela itu tidak menulis ulang aktivitas.
- Refresh satu jamaah menginvalidasi cache statistik agar perubahan pembayaran langsung terlihat pada pembacaan berikutnya.
- Batas body dan timeout mengendalikan penggunaan memori/koneksi untuk input yang tidak wajar.
- Kode TypeScript sekarang dapat memeriksa modul JS shared melalui inference; ketidakcocokan tipe flight, hotel, dan event instalasi diperbaiki. Ditambahkan command `npm run typecheck`.

Build masih memberi peringatan ukuran `vendor-pdf-renderer` sekitar 1.574 kB (gzip 527 kB). Bundle ini sudah lazy dan dikecualikan dari precache PWA. Pengurangan lebih lanjut merupakan kandidat optimasi khusus fitur PDF yang perlu diukur bersama kualitas hasil render.

## Batas dan catatan operasional

- Deployment produksi belum dilakukan. Backend, bundle SPA, landing functions, dan lockfile perlu dirilis bersama melalui workflow deployment yang berlaku.
- JWT dashboard yang sudah ada tetap memakai masa berlaku lama. Status/role kini mengikuti data agent terkini, tetapi pencabutan seluruh sesi pada perubahan password belum memiliki token-version persisten. Revocation/rotasi refresh token membutuhkan perubahan kontrak sesi dan migrasi tersendiri.
- Data akun untuk autentikasi memakai cache server dengan TTL lima menit. Perubahan melalui endpoint akun menginvalidasi cache; perubahan langsung pada database dapat menunggu TTL. Ketika refresh database gagal, perilaku cache lama tetap dipertahankan untuk ketersediaan; autentikasi tanpa cache ditolak sementara dengan 503.
- Limiter berada pada satu proses; restart menghapus hitungan. Deployment multi-instance membutuhkan penyimpanan limiter bersama.
- Event UI CAPI tetap publik untuk pelacakan pengunjung. Pembatasan jenis/payload dan limiter mengurangi penyalahgunaan, tetapi tidak membuktikan bahwa setiap pengunjung adalah manusia. Sync Purchase server tetap menjadi sumber nilai transaksi.
- File CAPI lokal yang ditemukan sudah terenkripsi. Penghapusan dari tracking bukan penghapusan history Git atau rotasi credential provider. Bila credential plaintext pernah dipublikasikan, rotasi tetap perlu dilakukan pada provider.
- Pemeriksaan anonim yang dilakukan tidak menemukan baris jamaah, sesi portal, atau konfigurasi CAPI yang dapat dibaca oleh role anon; kolom password agent dan grant OAuth ditolak. Pemeriksaan ini tidak menggantikan audit seluruh policy/backup database.
- Alur yang menulis ke sistem eksternal diuji dengan fixture/mock, bukan transaksi jamaah sungguhan. Tidak ada jaminan bahwa seluruh kombinasi data/provider/browser telah terjangkau pengujian.
